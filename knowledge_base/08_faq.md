AI 核心模型、Web 主介面及 Flask 後端主體不是她的主要分工，不能把整個團隊專案描述為由她獨立完成。

## 她有自己訓練模型嗎？

SEER 整體流程包含使用資料集進行模型訓練，她也理解從影像標註、人工審核、資料集匯出到模型訓練的流程；但核心模型與訓練模組不是她已確認的主要分工，不應描述為由她獨立設計或完成。

## 為什麼 SEER 要把 Cloud Run Service 和 Job 分開？

一般 API 應快速回應，但圖片處理與 AI 推論可能需要較長時間。Cloud Run Service 處理登入驗證、任務建立與查詢等短請求；Cloud Run Job／背景 Worker 處理耗時任務，可降低 HTTP Request Timeout 風險，也方便系統保存與追蹤任務狀態。

## 為什麼要先 Commit Task 再觸發背景工作？

若資料庫交易尚未 Commit 就啟動 Worker，Worker 可能查不到剛建立的 Task。先保存並完成交易，再觸發背景工作，可以確保 Worker 啟動時任務資料已存在。

她在專案中接觸並整合 Cloud Run Service、Cloud Run Job、Cloud SQL、Cloud Storage 與 Secret Manager。她理解容器本機檔案不適合作為永久儲存位置，因此將任務狀態保存在資料庫，圖片與輸出檔案保存在 Cloud Storage。

這些屬於專案實作經驗，不應擴張為精通所有 GCP 服務、雲端網路或企業級雲端架構。
